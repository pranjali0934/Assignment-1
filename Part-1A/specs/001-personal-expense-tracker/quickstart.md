# Quickstart: Personal Expense Tracker

## Prerequisites

- .NET 10 SDK installed
- Node.js + Angular CLI (for Angular 21) installed
- A SQL Server instance reachable for local development (e.g. SQL Server Express/Developer
  edition, or a SQL Server container) with a connection string set in
  `src/backend/appsettings.json`. If using Windows/Integrated Authentication
  (`Trusted_Connection=True`), the connection string has no credentials and can be committed
  as-is. If using SQL Server Authentication (username/password), keep the password out of the
  committed file (e.g. via .NET User Secrets or an environment variable) rather than hardcoding it.

## Setup

```powershell
# Backend
cd src/backend
dotnet restore
dotnet ef database update   # applies migrations to the configured SQL Server database

# Frontend
cd ../frontend
npm install
```

## Run

```powershell
# Terminal 1 — backend API
cd src/backend
dotnet run

# Terminal 2 — frontend
cd src/frontend
ng serve
```

Frontend will be available at `http://localhost:4200`, calling the API (default
`http://localhost:5000` or the port `dotnet run` reports).

## Validation scenarios (end-to-end proof the feature works)

1. **Create and validate an expense**
   - `POST /api/expenses` with `{"amount": 500, "category": "Food", "date": "<today>"}` →
     expect `201 Created`.
   - `POST /api/expenses` with `{"amount": 500.50, ...}` → expect `400 Bad Request`.
   - `POST /api/expenses` with a future `date` → expect `400 Bad Request`.

2. **Filter expenses**
   - Create expenses in `Food` and `Transport` on different dates.
   - `GET /api/expenses?category=Food` → only `Food` expenses returned.
   - `GET /api/expenses?from=<earlier>&to=<later>` → only expenses in that range returned.

3. **Monthly summary and budget alert**
   - Create two `Food` expenses totalling ₹700 in the current month.
   - `POST /api/budgets` with `{"category": "Food", "year": <y>, "month": <m>, "limitAmount": 500}`.
   - `GET /api/summary?year=<y>&month=<m>` → `byCategory` entry for `Food` shows `total: 700`,
     `budgetLimit: 500`, `overBudget: true`.

4. **Edit and delete**
   - `PUT /api/expenses/{id}` to change the amount → confirm the summary total updates
     accordingly on the next `GET /api/summary` call.
   - `DELETE /api/expenses/{id}` → confirm it no longer appears in `GET /api/expenses` or in the
     summary total.

Run `tests/backend` (xUnit) to execute these same scenarios as automated contract tests before
treating the feature as implemented — see `tasks.md` (generated by `/speckit-tasks`) for the full
test breakdown.
